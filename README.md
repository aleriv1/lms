# Корпоративная система обучения

Учебный проект LMS для внутреннего обучения сотрудников предприятия. Администратор управляет пользователями и назначениями, преподаватели готовят курсы, уроки и тесты. Сотрудники проходят назначенное обучение, а система сохраняет прогресс, результаты попыток и статистику.

## Требования

- Node.js 24 LTS и npm.
- Docker с Docker Compose для MongoDB; Docker должен быть запущен.
- Свободные порты 27017 (MongoDB), 4000 (API) и 5173 (клиент).

## Установка

Откройте терминал в корне скачанного репозитория:

```sh
npm install
npm run build -w shared
```

Корневой `npm install` устанавливает все три workspace: `client` (React/Vite), `server` (Express/Mongoose) и `shared` (контракты Zod и типы). Отдельная установка в папках не нужна. Сборка `shared` нужна перед первым запуском seed, сервера или проверки типов; повторяйте её после изменения контрактов.

## Переменные окружения

Скопируйте `server/.env.example` в `server/.env`. В PowerShell:

```powershell
Copy-Item server/.env.example server/.env
```

В Bash команда копирования — `cp server/.env.example server/.env`. Откройте созданный файл и замените заглушку `JWT_SECRET` собственным случайным значением длиной не менее 32 символов. Файл `.env` не включается в Git.

- `NODE_ENV` — режим работы: для локального запуска `development`, также поддерживаются `test` и `production`.
- `PORT` — порт API, по умолчанию в примере 4000; при изменении согласуйте прокси в `client/vite.config.ts`.
- `MONGODB_URI` — адрес и имя базы MongoDB; пример рассчитан на локальную MongoDB, запущенную через Compose.
- `CLIENT_ORIGIN` — разрешённый адрес клиента для CORS, в примере `http://localhost:5173`.
- `JWT_SECRET` — секрет подписи сессии; задаётся локально, не публикуется и не передаётся клиенту.

## База данных

Все команды выполняются из корня проекта:

```sh
npm run db:up
npm run db:down
```

Первая команда запускает MongoDB в фоне, вторая останавливает контейнеры. Данные хранятся в Docker volume и сохраняются после `db:down`. Команда `npm run dev` намеренно не запускает MongoDB: сначала выполните `db:up`.

## Демонстрационные данные

После настройки окружения и запуска MongoDB:

```sh
npm run seed
```

Команда создаёт отсутствующие записи и печатает результат для каждой сущности. Она не удаляет и не перезаписывает существующие данные. Повторный запуск ничего не создаёт, если весь набор уже есть.

**Существующая база не обновляется до новой версии демонабора.** Если seed пропустил хотя бы одну запись, последняя строка предупреждает об этом. Для получения текущего набора с нуля предусмотрена отдельная команда:

```sh
npm run seed:reset
```

**`seed:reset` удаляет все данные семи коллекций выбранной базы:** пользователей, курсов, уроков, тестов, назначений, прогресса уроков и попыток. Это касается и записей, созданных вручную. Перед удалением команда печатает имя базы, затем создаёт демонабор заново; при `NODE_ENV=production` она отказывается работать и возвращает ненулевой код. Перед запуском проверьте выбранную базу в `server/.env` и сохраните нужные данные.

Чистый набор содержит 12 пользователей, 5 курсов, 14 уроков, 4 теста, 8 назначений, 16 записей прогресса и 6 попыток. В нём есть опубликованные, черновой и архивный курсы, отозванное назначение, частичный прогресс и опубликованный курс без назначений. Даты учебных действий распределены по трём последним неделям относительно запуска seed.

## Запуск

```sh
npm run dev
```

Команда запускает сервер и клиент в режиме наблюдения за файлами. Откройте [страницу входа](http://localhost:5173/login): клиент работает на порту 5173, API — на порту 4000; Vite перенаправляет запросы `/api` на API. Для остановки нажмите Ctrl+C в терминале; MongoDB останавливается отдельно командой `npm run db:down`.

## Сборка и проверки

```sh
npm run build
npm run typecheck
npm run lint
npm run test
```

`build` последовательно собирает `shared`, сервер и клиент. Результат находится в `shared/dist`, `server/dist` и `client/dist`; свежая сборка сервера не включает тесты и `setupTests`. `typecheck` проверяет типы всех трёх workspace, включая тесты, `lint` проверяет исходный код, `test` запускает автоматические тесты сервера и клиента. Эти проверки не требуют запуска `dev`.

## API

- `/api/auth` — регистрация, вход, выход и текущая сессия.
- `/api/users` — собственный профиль и пароль пользователя.
- `/api/courses` — каталог, управление курсами, их уроками и тестами.
- `/api/learning` — назначенные курсы, прохождение уроков, отправка попыток и собственная статистика.
- `/api/admin` — пользователи, назначения, сводные показатели и статистика обучения.
- `/api/lessons/:id` и `/api/tests/:id` — чтение отдельного урока или теста по идентификатору для преподавателя и администратора; создание и редактирование живут внутри `/api/courses`.
- `/api/health` — проверка доступности API без авторизации.

Сессия хранится в `httpOnly` cookie. Ошибки имеют форму `{ code, message, fields? }`: `code` — машинный код, `message` — сообщение, необязательный `fields` — ошибки полей. Ответы списков используют `{ items, meta }`, где `meta` содержит `page`, `pageSize`, `total` и `totalPages`.
