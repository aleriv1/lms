# Срез 05, серверная половина — самоотчёт

Исполнитель — Claude. Спека — `.claude/specs/slice-05-server.md`. Формат по
AGENTS.md (8).

## 1. Что сделано

**Модель.** `server/src/models/Test.ts` по образцу `Lesson.ts`: поля из
раздела 4 спеки, вопросы и варианты — поддокументы со своими `_id`, два
индекса (`{ courseId }` и частичный уникальный `{ lessonId }`). Тип
`TestRecord` — атрибуты плюс `_id`, как у урока. Проекции `toTest` и
`toTestSummary` сортируют вопросы по `order`; `toTestSummary` не отдаёт
`isCorrect` вовсе.

**Вопросы.** `server/src/tests/questionRules.ts` — `buildQuestions`:
проверяет уникальность `order` (при повторе `422` с полями
`questions.<индекс>.order`), сортирует по `order` и присваивает
идентификаторы вопросам и вариантам.

**Связь.** `server/src/tests/testLink.ts` — пять функций из раздела 5 спеки:
`ensureTestLinkIsFree` (сторона теста), `ensureTestCanBeAttached` и
`attachTestToLesson` (сторона урока), `findLinkedTestId` (производное
значение для проекций), `assertLessonHasNoTest` (запрет удаления урока с
тестом). Плюс `lessonTestConflictError` — общий `409` для проверки и для
гонки на индексе.

**Доступ.** `server/src/tests/testAccess.ts`: `loadCourseTest` (курс сначала
— `403` из `loadOwnedCourse`, затем `404` на тест) и `loadTestById` (тест
сначала — `404`, затем права по его курсу — `403`). Один в один с
`lessonAccess.ts`.

**Маршруты.** `server/src/routes/courseTests.ts` — create, patch, delete;
роутер с `mergeParams: true`, смонтирован в `routes/courses.ts` рядом с
уроками. `server/src/routes/tests.ts` — плоский `GET /tests/:testId` со
своими `requireAuth, requireRole`, смонтирован в `routes/index.ts`.

**Состав курса.** `server/src/courses/courseDetail.ts` — `buildCourseDetail`:
уроки, тесты и карта `lessonId → testId` в одном месте. Обе копии сборки
`courseDetail` (`GET /courses/:courseId` и `reorder`) заменены вызовом.

**Правки в написанном.** `toLesson` и `toLessonSummary` принимают `testId`
вторым обязательным аргументом; `ensureTestExists` из среза 04 удалён;
`POST` урока проверяет тест до создания и привязывает после; `PATCH` урока
привязывает при непустом `testId` и игнорирует `null`; `DELETE` урока
отказывает `409`, если у урока есть тест; `publish`, `unpublish` и
`GET /lessons/:lessonId` дочитывают связь.

**Сид.** Один демонстрационный тест на опубликованном уроке курса «Вводный
инструктаж по охране труда»: вопросы `single` и `multiple`, идемпотентно по
паре `{ courseId, title }`.

**Тесты.** `server/src/tests/questionRules.test.ts` — 8 случаев: сортировка,
один вопрос, уникальность присвоенных идентификаторов, отказ на повторный
`order`, плюс четыре разбора `createTestBodySchema`, показывающих, что
правила ТЗ 4.4 отсекает схема до обработчика.

Зависимостей не добавлял.

## 1а. Приёмка

`npm run typecheck`, `npm run lint`, `npm run build`, `npm run test` —
зелёные (сервер: 8 файлов, 40 тестов; клиент: 3 файла, 10 тестов).

Сверх машинного гейта — одна точечная проверка на поднятой базе, потому что
частичный индекс живёт в Mongo, а не в типах, и ошибка в нём не видна ни
компилятору, ни модульному тесту. `npm run seed` создал демонстрационный
тест, после чего прямыми запросами к драйверу проверено:

- индексы коллекции `tests` — `_id_`, `courseId_1` и `lessonId_1` с
  `unique: true` и `partialFilterExpression: { lessonId: { $type: "objectId" } }`;
- вставка второго теста с тем же `lessonId` отклоняется с кодом `11000`, то
  есть правило «у урока не больше одного теста» держит база;
- две записи с `lessonId: null` в одном курсе индекс пропускает — значит
  правило «один итоговый тест на курс» действительно держится только
  обработчиком, как и написано в спеке.

Временные документы удалены, дев-сервер не запускался, браузер не
открывался. Остальные сценарии раздела 10 спеки — в чек-листе ниже.

## 2. Где отступил от спеки

**Идентификаторы вопросов и вариантов присваивает `buildQuestions`, а не
Mongoose.** Спека раздела 4 говорила обратное. Причина обнаружилась при
реализации: чтобы проекция читала `question._id` без утверждения
не-null, `_id` должен быть обязательным полем в типе поддокумента, а тогда
присвоение `test.questions = <разобранный ввод>` не проходит по типам —
во вводе `_id` нет. Варианты были: ослабить тип и читать `_id` небезопасно,
кастовать при присвоении или присваивать явно. Выбран третий: он не
добавляет ни `any`, ни утверждений и делает видимым, что при каждом
сохранении идентификаторы новые. Текст спеки исправлен той же правкой, в
разделе 4 отмечено, что это поправка.

**`isDuplicateKeyError` переехал** из `server/src/lessons/lessonOrder.ts` в
новый `server/src/db/duplicateKey.ts`. Раздел 8 спеки этого файла не
называл. Хелпер описывает ошибку Mongo, а не порядок уроков, и тестам он
понадобился вторым потребителем: импортировать из модуля про порядок уроков
код про тесты было бы связью без причины. Затронуты `lessonOrder.ts`,
`lessonOrder.test.ts` и `courseLessons.ts` — только строки импорта.

**Привязка теста в `POST` урока вынесена за `try`, ловящий `11000`.** Спека
описывала порядок «создать урок, затем привязать», но не говорила, где
проходит граница блока. Внутри блока конфликт уникальности по тесту
превратился бы в сообщение про занятый порядковый номер урока — чужой
`409` под чужим текстом.

Разделы 3, 5 и 6 спеки (маршруты, правила связи, коды отказа) выполнены
буквально. Противоречий спеки самой себе или с ТЗ не нашёл.

## 4. Замеченное вне рамок

- **Урок с тестом теперь нельзя удалить, а клиент среза 04 об этом не
  знает.** Отказ приходит как `409` с сообщением, и `LessonEditPage` с
  `LessonList` показывают `error.message`, так что пользователь текст
  увидит. Но кнопка удаления не отличает этот случай заранее, и подсказки
  «сначала отвяжите тест» на экране нет. Клиентской половине 05 стоит это
  учесть.
- **`shared/src/tests.ts` пишет `.default(70)` числом**, хотя рядом в
  `shared/src/constants.ts` лежит `DEFAULT_PASSING_SCORE = 70`. Второй
  источник правды на ровном месте; чинить в срезе 11 вместе с дефолтами
  update-схем.
- **`questionInputSchema.order` ничем не ограничен сверху и не связан с
  позицией в массиве.** Сервер требует только уникальности, поэтому тест с
  номерами 1, 5, 900 законен. Для уроков дырки в нумерации уже признаны
  допустимыми, здесь то же самое, но клиентской форме придётся самой решать,
  проставляет она номера по позиции или даёт их редактировать.
- **Инвариант «у курса один итоговый тест» держится только обработчиком.**
  Гонка двух одновременных `POST` его обойдёт: индекса под равенство `null`
  нет (проверено, см. выше). Цена гонки — второй итоговый тест в курсе,
  который автор увидит в составе курса и удалит. Транзакции недоступны по
  той же причине, что у `reorder`: Mongo поднят одиночным контейнером.
- **`GET /courses/:courseId` теперь делает три запроса вместо двух.** На
  странице курса это нормально, но если понадобится список курсов с
  тестами, `buildCourseDetail` для него не годится — там нужна агрегация,
  как у `lessonsCount`.

## Проверить руками

Начать с `npm run db:up` и `npm run seed`; работать под
`teacher@lms.local` / `Password1`. Курс «Вводный инструктаж по охране
труда» открывается со страницы `/manage/courses`; идентификаторы курса и
уроков видны в ответе `GET /api/courses/:courseId`. Запросы удобно слать
любым REST-клиентом с cookie сессии.

1. **Демонстрационный тест на месте.** `GET /api/courses/:courseId` —
   в `tests` один тест, `questionsCount: 2`, `version: 1`; у первого урока
   в `lessons` поле `testId` совпадает с его `id`, у второго — `null`.
   Успех: связь видна с обеих сторон без единого запроса к тесту.
2. **Итоговый тест курса.** `POST /api/courses/:courseId/tests` с телом
   `{ "title": "Итоговый тест", "lessonId": null, "questions": [<один
   валидный вопрос>] }` — `201`, `passingScore: 70`, `version: 1`, у
   вопроса и у каждого варианта заполнен `id`. Повторить тот же запрос —
   `409` «У курса уже есть итоговый тест».
3. **Тест на занятом уроке.** Тот же `POST` с `lessonId` первого урока —
   `409` «У урока уже есть тест». С `lessonId` второго урока — `201`.
4. **Чужой урок.** Тот же `POST` с `lessonId`, взятым из другого курса, —
   `404` «Урок не найден», а не `422`.
5. **Правила вопроса.** `POST` с двумя вопросами, у которых `order: 1`, —
   `422`, в `fields` ровно один элемент с `field: "questions.1.order"`.
   Отдельно `POST` с вопросом `type: "single"` и двумя правильными
   вариантами — `422` с `field: "questions.0.options"`.
6. **Полная замена при правке.** `PATCH
   /api/courses/:courseId/tests/:testId` итогового теста с другим составом
   вопросов — `200`, `version` стал `2`, вопросы заменены целиком, `id`
   вариантов отличаются от прежних. Успех: старые идентификаторы не
   сохранились — это и есть причина, по которой попытка (срез 08) будет
   хранить снимок.
7. **Плоское чтение.** `GET /api/tests/:testId` того же теста — `200`, у
   вариантов есть `isCorrect`. Успех: экран `/manage/tests/:testId/edit`
   получает всё нужное, не зная `courseId`.
8. **Связь со стороны урока.** `PATCH
   /api/courses/:courseId/lessons/:lessonId` второго урока с телом
   `{ "testId": "<id итогового теста>" }` — `200`, в ответе `testId` тот
   самый. Тот же запрос с `testId` теста, уже стоящего на первом уроке, —
   `409` «Тест уже привязан к другому уроку». Затем `PATCH` того же урока
   с телом `{ "title": "Средства индивидуальной защиты" }` — `200`, и
   `testId` в ответе **не** обнулился. Последнее — главная ловушка этой
   половины: форма урока шлёт `testId: null` на каждом сохранении.
9. **Удаление.** `DELETE /api/courses/:courseId/lessons/:lessonId` второго
   урока — `409` «Сначала удалите или отвяжите тест урока». Затем `DELETE
   /api/courses/:courseId/tests/:testId` привязанного к нему теста —
   `204`, и повторный `DELETE` урока — `204`.
10. **Права.** Из-под второй учётной записи преподавателя (завести её через
    `/register`): `POST /api/courses/:courseId/tests` в чужой курс — `403`,
    `GET /api/tests/:testId` чужого теста — `403`, а не `404`. Успех: о
    чужом тесте узнают ровно так же, как о чужом курсе.

Дев-сервер после проверки гасится: `netstat -ano | grep ":4000" | grep
LISTENING`, затем `taskkill //PID <номер> //T //F`.
