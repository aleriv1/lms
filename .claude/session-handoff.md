- Коммит перед каждым переходом между этапами. Сообщения на английском: тема в повелительном наклонении до ~50 символов без точки, тело через пустую строку, переносы ~72 символа, объясняется зачем, а не что за файлы. Одна тема на коммит.

## Принятые решения

- TypeScript strict на фронте и бэке; общий пакет Zod-схем = валидация + типы + резолвер RHF.
- CSS Modules + собственные примитивы (Button, Input, Select, Modal, Table, Pagination, Loader, EmptyState, ErrorState). Готовые UI-киты не берём.
- `Course.level` → `Course.audience` (направление/категория персонала); демо-данные — корпоративное обучение, не курсы по вёрстке.
- MongoDB + mongoose с самого начала. Промежуточного JSON-хранилища не будет.
- Стек курса: React, React Router, Redux Toolkit, RHF, Node + Express, Mongoose. Код канонически простой, без самодельных абстракций.
- `shared/` — пакет `@lms/shared` на zod 4 (`z.email()`, `z.iso.datetime()`), TS NodeNext с расширением `.js` в импортах, сборка в `dist/`. Корневой `package.json` с `workspaces` заводит Codex в первом срезе.
- Сообщения валидации на русском живут во входных схемах `shared/`; клиент их не переводит.
- Порядок срезов следует логике учебного курса; после каждого backend-среза Claude пишет короткий разбор (15–20 строк) для подготовки к защите.
- Цикл 1 Codex — вертикальное ядро (auth, роли, CRUD курсов/уроков, назначения, прохождение, тест). Цикл 2 — статистика, каталоги, сид, README, автотесты, правки.
- Длины текстов теста, вопроса и варианта ТЗ (4.4) не задаёт: границы доопределены в `shared/src/constants.ts`, помечены комментарием. Меняются одной правкой, если кураторы назовут свои.
- Смоук-тест схем (33 случая) лежит вне репозитория; переносится в `shared/` как контрактный тест в срезе 11.
- Минимальный `npm run seed` (три пользователя по ролям) появляется уже в срезе 02: без него срезы 03+ нечем проверять руками. Полный демо-набор раздела 12 ТЗ — срез 10.
- Поля `activityWeeks` и `recentActivity` на Этапе 1 отдаются пустыми массивами (так помечено в `shared/src/learning.ts`); то же правило распространяется на `userStatisticsSchema.recentActivity`. `activeUsersCount` на Этапе 1 считается по `LessonProgress.updatedAt` за 30 дней, с срезом 12 источник меняется на `ActivityEvent`.
- Версии инструментов держим актуальными, а не «как в примерах курса»: ТЗ v1.2 — React 19, Node 24 LTS, Express 5. Кураторы версий не задают, `project-tech-requirements.md` перечисляет только стек. Express 5 выбран из-за штатной передачи ошибок async-обработчиков в централизованный обработчик.
- Окружение разработчика: Node через nvm (нужен 24), MongoDB не ставится в систему — поднимается контейнером Docker, сервер видит её по строке подключения из `.env`. Codex работает локально в той же папке, поэтому база у него и у разработчика одна.

## Открытые вопросы

Форма пункта: вопрос — где лежал бы ответ — что блокирует. Без указателя на источник пункт не заводится: записать указатель значит сходить и проверить. Ответ найден — строка переезжает в «Принятые решения» той же правкой, а не удаляется.

- Формат сдачи (репозиторий, архив, деплой). Источник: кураторы; в `materials-for-thoughts/` требований к сдаче нет, ТЗ (10) описывает только команды проверки. Не блокирует код, нужен к финалу.

## Ревью срезов (три слоя)

1. Машина: `tsc`, линт, тесты, сборка + сверка со списком файлов среза. Гоняет сам Codex до конца среза.
2. Codex со свежим контекстом по чек-листу Claude: соответствие Zod-контракту, необработанные состояния, мёртвый код, пропущенные пункты.
3. Claude — только риск-зоны и замысел: права доступа и обход по URL, серверные расчёты прогресса и баллов, утечки в ответах API, состояния loading/empty/error, расхождение с промптом.

Каждый срез Codex закрывает самоотчётом: что сделано по чек-листу, где отступил и почему, что не смог. Claude читает отчёт и точечные куски диффа, не дифф целиком.
