# Claude session handoff — курсовая LMS

Живой файл: **перезаписывается**, не копится. Читать первым в новой сессии.

Размер — диагностика, а не квота. Счёт: `awk 'NF && !/^#/' .claude/session-handoff.md | wc -l`. Норма 45–55 содержательных строк; выше 60 — сигнал, что в файл заполз пересказ. Тогда искать дублирование и удалять строки целиком, а не ужимать формулировки ради числа: правка ради счёта тратит сессию и портит текст, а урезанная формулировка читается хуже полной.

Объём держат три правила, а не потолок:

- «Текущий этап» и «Следующий шаг» переписываются целиком каждую сессию, к ним не дописывают. Разносило всегда их.
- Решение выбывает из «Принятых решений», как только закреплено в файле из «Где истина» или в самом коде.
- Файл не пересказывает эти файлы — только ссылается на них.

## Режим работы

- Claude: ТЗ, контракты, план срезов, промпты для Codex, ревью. Код пишет Codex.
- Промпты для Codex — на английском, строгие: точный список файлов, готовые сигнатуры и Zod-схемы, зафиксированные версии зависимостей, команда проверки, запрет на архитектурные решения.
- Каждый срез — новая сессия Codex, и промпт-правка по итогам ревью тоже уходит в свежую сессию, а не в ту, что делала срез. Сессия-автор защищает свои решения вместо чтения промпта заново. Если промпт непонятен без старой сессии — чинить промпт, а не тянуть сессию.
- Команда Codex на новую сессию — одна строка без пересказа задания, чтобы не заводить второй источник правды: `Read AGENTS.md, then .codex/prompts/slice-NN.md, and do exactly what it says.` Промпт-правка — `slice-NN-fix.md`, отчёт по ней Codex кладёт в `.codex/reports/slice-NN-fix.md`.
- Команда Claude на новую сессию — `Ревью среза NN. Читай .claude/session-handoff.md, затем .codex/reports/slice-NN.md.` (для правки — `slice-NN-fix.md`). Больше в команде ничего не нужно: этот файл ведёт к промпту, плану и риск-зонам сам.
- Обе команды выдаются готовыми к копированию, а не подразумеваются. Написал промпт — в том же ответе даёшь команду запуска Codex и свою команду на возврат в ревью. Закрыл ревью — даёшь свою команду на следующую сессию. Пользователь уходит из сессии сразу после ответа, и невыданная команда стоит ему хода на её восстановление уже без контекста.
- Гасить всё, что запустил, до конца сессии: дев-сервер под `tsx watch` переживает собственное падение и держит порт, а следующий запуск падает с `EADDRINUSE` и выглядит дефектом кода. Проверка — `netstat -ano | grep ":4000" | grep LISTENING`, снятие — `taskkill //PID <номер> //T //F`. Контейнер `lms-mongo` гасить не надо. То же правило для Codex — AGENTS.md (8).
- Не читать сгенерированный код сплошь. Ревью по контракту + точечно: права доступа, серверные расчёты, работа с состоянием.
- Ресурс: два недельных цикла Codex, один Claude.
- Уровень рассуждений Codex: medium на механических срезах (01, 04, 05, 10), high там, где сервер может быть неправ молча и это не поймает ни компилятор, ни тест (02, 03, 06, 07, 08, 09, 11, 12). Low не использовать.
- Коммит перед каждым переходом между этапами. Сообщения на английском: тема в повелительном наклонении до ~50 символов без точки, тело через пустую строку, переносы ~72 символа, объясняется зачем, а не что за файлы. Одна тема на коммит.
- После каждого среза с логикой Claude пишет разбор на 15–20 строк для защиты.

## Принятые решения

Здесь только то, что не закреплено ни в одном файле из списка выше.

- TypeScript strict везде; общий пакет Zod-схем = валидация + типы + резолвер RHF. Дублировать схемы в `client/` или `server/` нельзя.
- CSS Modules + собственные примитивы. Готовые UI-киты не берём.
- Версии актуальные, а не «как в примерах курса»: React 19, Node 24 LTS, Express 5 (ТЗ v1.2). Кураторы версий не задают. Express 5 выбран из-за штатной передачи ошибок async-обработчиков в централизованный обработчик — обёртка `catchAsync` запрещена.
- Окружение: Node 24 через nvm (активна), MongoDB контейнером в Docker, в систему не ставится. Codex работает локально в той же папке — база у него и у разработчика одна. `npm run db:up` к `npm run dev` не цепляется: дев-сервер не должен молча дёргать Docker и падать невнятно при выключенном движке.
- Сообщения валидации на русском живут во входных схемах `shared/`; клиент их не переводит.
- Сервер API-only: клиент собирается Vite и раздаётся отдельно, ТЗ раздачи статики сервером не требует. Поэтому `notFound` отвечает контрактным JSON на любой непойманный путь, а не только под `/api`.
- Маршрут добавляет тот срез, который его обслуживает; пустых страниц-заглушек по разделу 6 ТЗ не заводим.
- Смоук-тест схем (33 случая) лежит вне репозитория, переносится в `shared/` как контрактный тест в срезе 11.
- Таблицу маршрутов в промптах не переписывать плоским списком: структура живёт в `client/src/App.tsx`, промпт называет только маршрут, который добавляет, и куда он вкладывается. Плоский список в промпте 02 противоречил требованию «404 внутри оболочки с сайдбаром», и Codex разрешил противоречие молча.

## Открытые вопросы

Форма пункта: вопрос — где лежал бы ответ — что блокирует. Без указателя на источник пункт не заводится. Ответ найден — строка переезжает в «Принятые решения» той же правкой.

- Формат сдачи (репозиторий, архив, деплой). Источник: кураторы; в `materials-for-thoughts/` требований к сдаче нет, ТЗ (10) описывает только команды проверки. Не блокирует код, нужен к финалу.

## Ревью срезов (три слоя)

1. Машина: `typecheck`, `lint`, `build`, `test` + сверка со списком файлов среза. Гоняет сам Codex до конца среза.
2. Codex со свежим контекстом по чек-листу Claude: соответствие Zod-контракту, необработанные состояния, мёртвый код, пропущенные пункты.
3. Claude — только риск-зоны и замысел: права доступа и обход по URL, серверные расчёты прогресса и баллов, утечки в ответах API, состояния loading/empty/error, расхождение с промптом.

Codex сдаёт срез одним коммитом и самоотчётом, затем останавливается: без push, без amend. Коммиты ревью ложатся сверху — видно, что сдал Codex и что изменило ревью. Закрыт срез или нет — решает ревью, сам он это не объявляет. Claude читает отчёт и точечные куски диффа, не дифф целиком.

## Когда переходить в новую сессию

Три шва, у каждого своя причина — не смешивать:

- **Ревью и приёмка среза — всегда свежая сессия. Причина: независимость.** Сессия, писавшая промпт, защищает свои формулировки и читает код через свой замысел. Экономия тут ни при чём.
- **Промпт-правка по итогам ревью — в той же сессии, что нашла дефекты.** Кто нашёл, тот дешевле всех и опишет.
- **Промпт следующего среза — свежая сессия. Причина: экономия.** Написание промпта многоходовое, и каждый ход тащит весь накопленный контекст заново; класть его поверх сессии ревью значит платить за чужой рабочий набор на каждом ходу. Корпуса почти не пересекаются: ревью читает дифф и отчёт, промпт — план среза, разделы ТЗ и `shared/`. Побочная выгода: если промпт пишется из файлов и файлов хватает, значит их хватит и Codex. Промпт среза 02 написан в сессии приёмки как разовое исключение — корпус уже был загружен.

Плюс общие поводы: этап завершён и результат записан в файл; меняется тип работы; контекст начал суммироваться или ответы поплыли.

Перед выходом: обновить этот файл (этап, решения, следующий шаг, открытые вопросы).
