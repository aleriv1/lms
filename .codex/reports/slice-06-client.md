# Slice 06 client — self-report

## Выполнено

- Прочитаны AGENTS.md, промпт, соответствующие разделы ТЗ, shared-контракты и четыре обязательных образца клиента. Статически проверены adminUsers.ts, userAssignments.ts, подключение маршрутов, middleware валидации и отказы назначения: пять маршрутов, тела и ответы соответствуют промпту. DELETE возвращает Assignment с сохранённой историей.
- Добавлены usersApi, сериализация и чтение URL через adminUsersQuerySchema, шесть thunk с FormError и adminUsersSlice. Список защищён requestId; пустые фильтры не отправляются. Picker использует requestCourses и собственное состояние, не меняя courses.list.
- `/admin/users`: поиск по имени/email и группе с debounce и ограничениями длины, фильтры роли/статуса, сортировка и направление, таблица всех требуемых полей, серверная пагинация, loading/error/два empty/data. Ограничение номера страницы использует только meta запрошенной страницы. В CourseListPage внесены ровно две предусмотренные строки.
- `/admin/users/:userId`: загрузка карточки, отдельное отображение not_found и переход на forbidden по коду ошибки, форма пользователя, назначение и история. Оба маршрута используют существующий ProtectedRoute с ролью admin.
- AdminUserForm использует React Hook Form и общий Zod resolver с раздельными входным и выходным типами. PATCH всегда содержит name, role, groupName, status; email показан только в заголовке карточки. Пустую группу преобразует схема. Изменения роли/статуса подтверждаются Modal с прежними и новыми значениями; имя/группа сохраняются сразу. Серверные поля ошибок и общее сообщение отображаются, собственная роль/статус не проверяются на клиенте.
- Ответ PATCH заменяет карточку и строку списка с сохранением activeAssignmentsCount. Для своей карточки authSlice обновляет session user через publicUserSchema. Повторного GET после сохранения нет, форма не размонтируется.
- AssignmentForm загружает до 50 опубликованных курсов по названию, показывает ограничение при неполной выборке, оставляет уже активно назначенные курсы видимыми, но недоступными. courseId получает ошибку через setError; сообщения отказов пользователя и конфликтов показаны в общей области. Повторная отправка блокируется на время запроса.
- AssignmentList показывает курс и его статус, статус назначения, назначившего, обе даты и серверный progressPercent, включая 0%. Снятие подтверждается Modal с названием курса. POST добавляет ответ первым, DELETE заменяет строку по id, счётчик списка меняется на +1/-1 с нижней границей 0. Клиент не вычисляет прогресс, статусы и даты.
- Все новые стили — CSS Modules с существующими токенами и UI-компонентами. Добавлены только файлы из списка промпта и этот отчёт; четыре существующих файла изменены только для оговорённого подключения и исправления.

Ввести в поиск `student@lms.local`: после debounce остаётся Петров. Очистить поиск, ввести группу `Смена А`: остаётся Петров; заменить на `Смена Б`: Кузнецова и Смирнов. Выбрать статус «Активен»: остаётся Кузнецова. Проверить роль «Преподаватель» после очистки группы/статуса: два преподавателя. Вернуть «Все роли» и «Все статусы»: полный список без 422; в URL нет `role=`/`status=`. Свободные назначения не требуются.
2. **Пустой результат, сортировка, URL.** На `/admin/users` ввести `нет-такого-пользователя`: «Пользователи не найдены». Очистить, выбрать сортировку «Email», переключить направление: строки меняют порядок. Открыть `/admin/users?page=999&pageSize=10`: после ответа серверной страницы URL возвращается к page=1 и видны пользователи. Открыть `/manage/courses?page=999&pageSize=10`: аналогичное возвращение к последней странице каталога. При шести пользователях обычные кнопки пагинации скрыты существующим Pagination; дополнительные записи не создавать. Свободные назначения не требуются.
3. **История существующего назначения.** На `/admin/users` найти `student@lms.local` → «Открыть карточку», получив `/admin/users/:userId` без ручного подбора id. В базе после серверного ревью у него ожидаются одно active и одно revoked. Видны обе строки с датами, назначившим и прогрессом 0%; у снятого назначения нет кнопки «Снять». «Правила технической эксплуатации» остаётся в Select, но недоступен из-за active. В списке пользователей activeAssignmentsCount равен 1. Этот пользователь уже занят; его назначения в следующих шагах не менять.
4. **Имя, группа, валидация.** С `/admin/users` открыть `student2@lms.local`, у которого ещё нет active назначения. Очистить имя: русская ошибка, сохранение недоступно. Ввести `Обучающаяся Кузнецова`, очистить группу, сохранить: без Modal, сообщение об успехе, форма остаётся открытой. Перезагрузить карточку: группа пустая. Вернуть `Смена Б`, сохранить. В Network у PATCH присутствуют все четыре поля, пустая группа отправлялась как null, email отсутствует; после PATCH нет GET карточки.
5. **Роль и статус другого пользователя.** На карточке `student2@lms.local` из шага 4 (всё ещё свободен) выбрать роль «Преподаватель» и статус «Заблокирован», нажать сохранение: Modal называет пользователя и оба изменения. «Отмена» не меняет серверные данные.
