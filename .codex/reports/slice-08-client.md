# Slice 08 — клиент: прохождение теста

## Что сделано

- Решения 1–2: маршрут `/learning/tests/:testId` под обычным `ProtectedRoute` внутри `AppLayout`, ключ страницы без учёта регистра; ссылки из итогового теста курса и теста урока через `TestSummaryCard.canStart` с подписью по `attemptsCount`.
- Решения 3–4: сначала загружается тест, затем его курс; названия курса и урока — ссылки. Ошибка или загрузка курса не скрывает вопросы. Загруженный архивный курс показывает пустое состояние без формы.
- Решения 5–10: RHF и общий Zod-контракт, один вопрос за раз, radio/checkbox в `fieldset`, переходы с сохранением ответов, прогресс заполнения, подтверждение числа пропущенных вопросов. Отправляются все вопросы в исходном порядке, включая пустые `optionIds`. Синхронный ref-флаг проверяется до валидации, модального окна и запроса; кнопки блокируются, флаг освобождается в `finally`.
- Решения 11–13: результат заменяет форму; все показатели попытки отображаются из ответа сервера. После `passed` перечитываются курс и связанный урок; после неудачной попытки дополнительных чтений нет. Уведомление «Курс пройден» берётся из перечитанного назначения. Повтор очищает результат reducer-ом и монтирует новую форму. Есть ссылки обратно; редактирования отправленной попытки и прогресса курса на экране результата нет.
- Решения 14–16: отказы загрузки разобраны по `error.code`, с возвратом только в `/learning`; остальные ошибки имеют повтор запроса. Отказы отправки остаются над кнопками формы с сообщением сервера. Тест и результат хранятся в `learningSlice`, результат очищается на обеих новых pending-операциях и при повторе. Поздние результаты запросов покинутой страницы игнорируются через abort thunk-ов; первоначальное чтение курса не перезаписывает обновление после проходной попытки.
- Решение 17: три теста формы проверяют сохранение одиночного и множественного выбора, подтверждение двух пропущенных вопросов с отправкой полного тела, двойной клик и прямой `fireEvent.submit` при незавершённом запросе. Ещё два теста проверяют сохранение и очистку результата в Redux.
- Список файлов сверен: пять новых и восемь изменённых клиентских файлов из промпта плюс этот отчёт. В двух существующих страницах изменена только передача `canStart`. `server/`, `shared/`, зависимости, store и UI primitives не изменены.

## Отступления и противоречия

- Предупреждение об уходе с несохранёнными ответами из ТЗ 5.3 не реализовано: промпт явно исключает его из этого среза, а `.claude/slice-plan.md`, срез 13, откладывает общую миграцию с `BrowserRouter` на data router. Это остаётся невыполненным требованием ТЗ до среза 13; менять архитектуру роутера здесь не разрешено.
- Требование рендер-теста формы выполнено по ТЗ 13 и решению 17, несмотря на общий запрет таких тестов в AGENTS.md 9.
- Локальный `ActionError` находится в `TestAttemptForm.tsx`: при заданных пропсах именно форма получает возвращённый `FormError` и располагает его над отправкой. Страница возвращает ошибку из thunk, как требует контракт формы.
- Промпт называет два невоспроизводимых на сиде состояния, но их больше: также нет теста на блокируемом уроке и доступного обучающемуся теста из нескольких вопросов. Чек-лист отмечает эти ограничения вместо выдуманных URL или новых фикстур. Первое уже записано в срезе 10 плана; переходы между вопросами проверены автоматическим тестом.

- Пути, методы, cookie-аутентификация без role-gate → прочитаны `server/src/routes/index.ts`, `learning.ts`, `learningTests.ts` → `/learning/tests/:testId` и `/:testId/attempts` подключены под `requireAuth`, role middleware отсутствует.
- GET возвращает `LearnerTest`, POST — `201` и `AttemptResult` → прочитаны оба обработчика и `shared/src/tests.ts` → формы совпадают; ответы ученика не несут признаков правильности, результат не содержит прогресса курса.
- Отказы по назначению, архиву, блокировке, отсутствующему/невалидному id и конфликту → прочитаны `learningTests.ts`, `assignedCourse.ts`, `accessRules.ts`, `middleware/validate.ts` → соответствуют кодам промпта; чтение архива разрешено, отправка запрещена.
- Проходная попытка завершает связанный урок и проверяет завершение курса; непроходная сохраняется без изменения прогресса → прочитан POST в `learningTests.ts` → операции завершения находятся только в ветке `graded.passed`.
- Нет серверной дедупликации одинаковых попыток → прочитан `createAttempt` в `learningTests.ts` → резервируется очередной номер, одинаковые тела не сравниваются.
- Общий API-клиент отправляет cookie и централизованно обрабатывает 401 → прочитан `client/src/api/client.ts` → `credentials: include` и вызов обработчика авторизации присутствуют.
- Урок с тестом не имеет кнопки завершения → прочитан `LearningLessonPage.tsx`, проверен diff → условие `!lesson.requiredTest` и строка о завершении тестом сохранены.
- Стандартные входы в курс и урок существуют → прочитаны `CourseCard.tsx` и `LessonToc.tsx` → ссылка «Начать»/«Продолжить» ведёт на обзор, доступный урок открывается по названию.

- Повторный seed не очищает попытки и прогресс → прочитан `seed.ts` → существующие сущности и назначения пропускаются, сброса прогресса/попыток нет.

## Проверить руками

Начать с `/learning` под `student@lms.local` / `Password1`; при необходимости войти через `/login`. База уже должна содержать сид. **Рабочая база не свежая:** по промпту в ней десять попыток этого ученика, завершён «Журнал осмотров: как заполнять» и назначение на «Работа с диспетчерской системой» в `completed`. Повторный `npm run seed` этого не отменяет. Для пунктов с отметкой **свежая БД** нужна отдельная исходная база, подготовленная разработчиком. Не ожидать номер попытки 1 на рабочей базе.

1. **Вход из урока.** URL `/learning` → «Начать»/«Продолжить» у «Правила технической эксплуатации» → название «Журнал осмотров: как заполнять» в оглавлении → «Пройти тест» либо «Пройти тест ещё раз». Успех: открывается `/learning/tests/:testId`, видны название теста, ссылки с названиями курса/урока, проходной балл 70 %, «Вопрос 1 из 1» и radio-варианты. На уроке есть строка «Урок завершается прохождением теста», кнопки «Завершить урок» нет. Сохранить фактический URL теста из адресной строки для следующих пунктов.

2. **Пропуск и неудачная попытка — свежая БД для проверки незавершённого урока.** На URL теста из п. 1 оставить выбор пустым, нажать «Отправить ответы». Успех: диалог «Вопросов без ответа: 1», POST ещё не отправлен; отмена сохраняет форму. Снова отправить и подтвердить: результат 0 %, «Тест не пройден», 0 из 1, номер и дата попытки; форма исчезла. «Вернуться к уроку» возвращает к незавершённому уроку без кнопки завершения. На рабочей базе уже завершённый урок не должен становиться незавершённым.

3. **Успешный тест урока — свежая БД и п. 2 до первой успешной попытки для проверки перехода состояния.** Через ссылку урока вновь открыть тот же тест; выбрать «Сразу после осмотра», отправить. Успех: без подтверждения показаны 100 %, «Тест пройден», 1 из 1, новый номер попытки. В Network после POST выполнены чтения курса и урока. По «Вернуться к уроку» урок завершён, но «Завершить урок» по-прежнему отсутствует. Необязательность этого урока не позволяет ожидать увеличения процента курса.

4. **Повтор.** На URL теста из п. 1 после результата нажать «Пройти ещё раз». Успех: новая форма «Вопрос 1 из 1», оба radio не выбраны, заполнение 0 %, прежний результат не отображается. Отправка снова требует подтверждения одного пропуска.

5. **Вход в итоговый тест.** URL `/learning` → «Начать»/«Продолжить» у «Работа с диспетчерской системой» → ссылка в блоке «Итоговый тест». Успех: `/learning/tests/:testId` открывается со ссылкой на курс и без ссылки на урок; виден вопрос о приёме смены. Сохранить этот фактический URL. **На свежей БД** тест должен открываться и до завершения обязательного урока.

6. **Завершение курса — свежая БД для проверки перехода active → completed.** Из теста п. 5 вернуться к курсу, открыть «Прием и сдача смены», нажать «Завершить урок», вернуться к курсу и снова открыть итоговый тест. Выбрать «Осмотр оборудования и запись в журнал», отправить. Успех: 100 %, «Тест пройден»; после чтения курса появляется «Курс пройден». На рабочей базе повторная проходная попытка проверяет показ уведомления, но не переход статуса. В результате нет полосы прогресса курса; на странице курса данные берутся из сервера.

7. **Ошибка отправки с сохранением выбора.** На сохранённом URL любого теста открыть пустой повтор, выбрать вариант; в DevTools Network включить Offline и отправить. Успех: общая ошибка над кнопками, выбранный ответ остаётся, отправка снова доступна. Вернуть Online и повторить — появляется результат. Сетевая ошибка проверяет общий путь отказа; `409 conflict` на сиде детерминированно не вызывается.

8. **Повторный клик.** На том же URL в новой попытке выбрать вариант, включить замедление сети в DevTools, быстро дважды нажать «Отправить ответы». Успех: один POST `/api/learning/tests/.../attempts`, кнопка заблокирована до ответа, один результат. Прямой `submit`, обходящий кнопку, отдельно покрыт автоматическим тестом. После проверки отключить замедление.

9. **Курс не является условием показа вопросов.** На сохранённом URL теста в DevTools временно заблокировать только запросы `*/api/learning/courses/*`, перезагрузить страницу. Успех: вопросы доступны, названий курса/урока в заголовке нет; нет общей ошибки загрузки вместо теста. Снять блокировку после проверки.

10. **Отказы прямого URL.** Вставить `/learning/tests/not-an-id`: «404 — Тест не найден», ссылка только в `/learning`, боковое меню сохранено. Затем выйти, войти под `student2@lms.local` / `Password1` и вставить сохранённый URL из п. 1. На исходном сиде этому ученику курс не назначен: «Курс вам не назначен», возврат в `/learning`, без перенаправления на `/forbidden`. Вернуться под первым учеником. Для общего сбоя загрузки можно открыть тот же URL с Offline: видны ошибка и повтор; вернуть Online и повторить — тест загрузится.

11. **Прямая ссылка на тест заблокированного урока.** URL начала `/learning` → «Правила технической эксплуатации», посмотреть оглавление; целевой маршрут — `/learning/tests/:testId` теста закрытого урока. Результат: **не воспроизводится на текущем сиде**. У блокируемого урока «Периодичность осмотров» нет теста, а тест optional-урока 2 доступен с начала. Копируемого URL такого теста нет даже на свежей БД; не конструировать id. После расширения сида ожидаются «Тест пока закрыт» и только возврат в `/learning`; чтением обработчика проверен `403 lesson_locked`.

12. **Переходы с сохранением ответов.** URL — сохранённый тест из п. 1 или 5; предполагаемый ввод — выбор, «Далее», выбор, «Назад». Результат: **не воспроизводится на текущем сиде**, оба доступных теста одно-вопросные. Сохранение radio и нескольких checkbox при переходах туда и обратно проверено тестом `TestAttemptForm.test.tsx`; продуктовая проверка ждёт доступного теста минимум из двух вопросов.

13. **Архивный курс.** URL начала `/learning`; целевой маршрут — тест архивного назначенного курса. Результат: **не воспроизводится на текущем сиде**, архивных курсов нет. После расширения сида ожидается отсутствие ссылки запуска в курсе/уроке, а при вставке ранее сохранённого URL теста — «Курс в архиве: новые попытки недоступны», возврат в курс и `/learning`, без вопросов и отправки.

14. **Полный набор multiple-ответа.** URL начала `/learning`; целевой маршрут — тест с множественным выбором. Результат: **не воспроизводится на текущем сиде**: вопрос со средствами защиты находится в неназначенном черновом курсе. Не публиковать и не назначать его ради этой проверки. После расширения сида проверять полный правильный набор и неполный набор отдельными попытками; оценку должен возвращать сервер. Сам выбор и сохранение нескольких checkbox уже проверены тестом формы.
