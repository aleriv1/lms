# Slice 15 — браузерные e2e-сценарии

## 1. Что сделано

- Добавлены Playwright config, global setup, один UI login helper и три spec-файла: 10 сценариев, Chromium, один worker, без повторов. Suite B последовательно использует одну страницу для трёх попыток; остальные тесты получают отдельные контексты.
- Сервер запускается из сборки на 4100, клиент — Vite на 5273 с прямым `VITE_API_URL`; оба `webServer` имеют `reuseExistingServer: false`. Настройки передаются через окружение. JWT secret генерируется при запуске.
- Setup запускает собранный seed с `--reset` исключительно для `corporate-learning-e2e`, с ограничением времени и явной ошибкой при сбое. Новые фикстуры и назначения не создаются. Сценарии сохраняют изменения только существующих seed-курса/урока и отправляют предусмотренные попытки.
- Установлен точный `@playwright/test` 1.62.1. `npx playwright install chromium` выполнен один раз; Chromium/Headless Shell 151.0.7922.34, revision 1234. Firefox и WebKit не устанавливались.
- Добавлен отдельный `test:e2e`. Команда `test` не изменена. В `.gitignore` добавлены `playwright-report/` и `test-results/`; диагностический лог покрывается существующим `*.log`.
- Последний e2e gate: **10 PASS за 22,0 с**. Скриншоты, trace viewer и HTML report не открывались.

## 2. Отступления и противоречия

- `package-lock.json` обновлён вместе с разрешённой установкой зависимости, хотя в списке «Files» явно назван только `package.json`. Изменение lockfile ограничено Playwright и его зависимостями. Отчёт добавлен по отдельному требованию промпта.
- A4 редактирует seed-черновик «Подготовка к сезонному осмотру», чтобы не менять название курса, который читают B/C. A3 редактирует указанный урок вводного курса.
- A2 вызывает настоящий `window.location.reload()` внутри headless сценария: `page.reload()` после отмены beforeunload продолжал ждать событие `load` до тайм-аута. Тест проверяет реальный browser dialog типа `beforeunload`, отменяет его, проверяет URL и введённый текст; после очистки поля обычный `page.reload()` завершается без диалогов. Проверка не подменена наблюдением за регистрацией listener.
- Промпт говорит, что B снимает slice-13-client №8–10, но №10 — множественный выбор. Три предписанных сценария B проверяют одиночный выбор: №8–9 снимаются, №10 остаётся ручным.
- A2 проверяет общий механизм beforeunload на форме курса, но slice-14 №1 называет `/profile/edit`. Профильная часть этой проверки остаётся ручной. A5 снимает отдельные изменения двух форм и проверяет чистый уход; сочетание изменений обоих блоков из slice-13-client №12 остаётся ручным.
- Утверждение промпта о существующей независимости `npm run test` от Docker не подтвердилось. Существующий серверный integration gate требует настоящую MongoDB. Исправление затрагивает запрещённые серверные файлы и не выполнялось.
- Коммит не создан: требование пройти `npm run test` без Docker-базы не выполнено; AGENTS.md запрещает коммит при падающем обязательном требовании. Остальные изменения оставлены для review, срез не объявлен завершённым.

## 3. Что заблокировано

Проверка независимости обычного gate от базы: после `docker compose stop mongo` команда `docker compose ps --all --format json` подтвердила `lms-mongo: exited`. Затем `npm run test` завершилась с кодом 1 за 65,68 с: **9 серверных файлов FAIL, 19 PASS; 134 теста PASS, 91 SKIP**. Клиентская команда после отказа server не запускалась.

Причины: `connectTestDatabase` вызывает `connectToDatabase`, получая `ECONNREFUSED 127.0.0.1:27017` (также отказ IPv6); другие наборы упираются в тайм-аут общего database lock. Это существующий `server/src/testing/apiClient.ts`, а не включение Playwright в Vitest. Диагностика сохранена в игнорируемом `slice-15-unit-without-mongo.log`.

Docker Engine целиком не выключался: остановлен только контейнер MongoDB этого проекта. Уже отсутствие этого контейнера опровергает заявленную работу без базы. После проверки `npm run db:up` восстановил контейнер. Для завершения нужен отдельный разрешённый объём изменения существующего integration gate либо исправление требования промпта.
