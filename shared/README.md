# @lms/shared

Общий пакет контрактов: схемы Zod, выводимые из них типы, перечисления и константы.
Схемы этого пакета — **единственный источник истины** по формату запросов и ответов
(ТЗ, раздел 10.4). Их используют серверная валидация, типы клиента и сервера и
валидация форм через `zodResolver`. Дублировать определения в `client/` или
`server/` нельзя: недостающее поле добавляется здесь.

## Состав

| Файл | Содержание |
|---|---|
| `enums.ts` | роли, статусы, аудитории, типы вопросов и событий, коды ошибок API |
| `constants.ts` | числовые границы валидации, размеры страниц, окна статистики |
| `common.ts` | идентификаторы, даты, ссылки, пагинация, конверт списка, формат ошибки |
| `auth.ts`, `users.ts` | регистрация, вход, профиль, администрирование пользователей |
| `courses.ts`, `lessons.ts`, `tests.ts` | управляющая часть: курсы, уроки, тесты |
| `assignments.ts` | назначения курсов |
| `learning.ts` | прохождение обучения и статистика обучающегося |
| `statistics.ts` | главная администратора и статистика пользователей |
| `activity.ts` | события активности (Этап 2) |

## Соглашения

- На границе API все `_id` — строки (`objectIdSchema`), все даты — строки ISO 8601.
- Схемы с суффиксом `BodySchema` описывают вход, `QuerySchema` — параметры строки
  запроса (числа приводятся из строк через `z.coerce`), остальные — ответы.
- Проценты, баллы и права считает сервер; клиент их не вычисляет и не отправляет.
- Правильные ответы не входят в схемы, доступные обучающемуся: для тестов есть
  отдельная пара `testSchema` (администрирование) и `learnerTestSchema`.
- Сообщения об ошибках валидации на русском заданы во входных схемах, чтобы формы
  показывали их без перевода на клиенте.

## Команды

```
npm run typecheck
npm run build
```

Пакет подключается как рабочая область npm под именем `@lms/shared`; корневой
`package.json` с `workspaces` появляется вместе с `client/` и `server/`.
